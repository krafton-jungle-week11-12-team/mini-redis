# ADR 0003: 서버 구현 언어로 Python 사용

이 문서를 읽으면 mini-redis 서버를 왜 C나 Go가 아닌 Python으로 만드는지, 그 선택으로 무엇을 얻고 무엇을 포기하는지 알 수 있어요.

- 상태: 채택
- 날짜: 2026-11-13

## 결정

mini-redis 서버는 Python으로 구현해요. Python `socket`으로 연결을 다루고([ADR 0002](0002-socket-connection.md)), RESP로 통신해요([ADR 0001](0001-protocol-resp.md)).

## 비교

| 항목 | C | Go | Python |
| --- | --- | --- | --- |
| 진짜 Redis와 닮은 정도 | 가장 높아요 (Redis가 C) | 중간 | 중간 |
| 해시테이블 직접 구현 | 메모리 할당, key_len까지 직접 다뤄서 원리를 깊게 이해해요 | 구조체·슬라이스로 무난해요 | 리스트로 구현해요. 내장 dict를 쓰지 않도록 주의해야 해요 |
| 소켓·이벤트 루프 | socket, epoll을 직접 호출해요. 배우는 건 많지만 코드량도 많아요 | net 패키지로 간단해요. 클라이언트마다 goroutine을 쓰는 게 기본이에요 | asyncio로 단일 스레드 이벤트 루프를 쉽게 만들어요 |
| Phase 3 동시성 | 이벤트 루프 또는 스레드+락을 직접 설계해요 | goroutine 때문에 락 설계가 핵심 주제가 돼요 | asyncio면 Redis처럼 락 없는 구조가 자연스러워요 |
| 메모리·버그 위험 | 높아요 (메모리 누수, 버퍼 오버플로) | 낮아요 | 낮아요 |
| 개발 속도 | 느려요 | 빠른 편 | 가장 빨라요 |
| 성능 | 가장 빨라요 | 빨라요 | 느리지만 Phase 1~6 학습용으로는 충분해요 |

## 결과

- 개발 속도가 가장 빠르고, 메모리 누수나 버퍼 오버플로 위험이 낮아요.
- asyncio로 단일 스레드 이벤트 루프를 만들면 Phase 3 동시성에서 Redis처럼 락 없는 구조를 자연스럽게 가져갈 수 있어요.
- 해시테이블은 리스트로 직접 구현해요. 내장 dict를 쓰지 않도록 주의해야 해요.
- 성능은 C·Go보다 느리지만 Phase 1~6 학습용으로는 충분해요.
