# Mini Redis Phase 2 요구사항 명세서

Phase 2(API · 프로토콜)에서 구현할 요구사항이에요. 서버의 요청·응답 형식은 Phase 1(R-01 ~ R-04)에서 정했고, Phase 2에서는 그 서버를 쉽게 쓰는 클라이언트와 CLI를 만들어요. 서버는 바꾸지 않아요.

## 1. 클라이언트

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| R-26 | 사용자는 서버 주소와 포트를 지정해 클라이언트를 만들 수 있어야 한다. | 지정하지 않으면 `127.0.0.1:6380` |
| R-27 | 클라이언트는 서버가 지원하는 모든 명령어를 메서드로 제공해야 한다. | |
| R-28 | 클라이언트는 명령어 이름과 인자를 받아 그대로 서버에 보내는 범용 메서드를 제공해야 한다. | 서버에 명령어가 추가돼도 바로 쓸 수 있게 |
| R-29 | 클라이언트는 서버가 성공 응답을 주면 `result` 값을 그대로 반환해야 한다. | GET 결과가 없으면 `None` |
| R-30 | 클라이언트는 서버가 오류 응답을 주면 예외를 발생시켜야 한다. 예외에는 `error.code`와 `message`가 담겨야 한다. | |
| R-31 | 클라이언트는 서버에 연결할 수 없으면 예외를 발생시켜야 한다. | 서버가 꺼져 있거나 주소가 틀린 경우 |
| R-32 | 클라이언트는 응답이 제한 시간 안에 오지 않으면 예외를 발생시켜야 한다. 제한 시간은 초 단위 숫자로 지정할 수 있어야 한다. | 지정하지 않으면 5초. 무한정 기다리지 않게 |

## 2. CLI (선택)

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| R-33 | 사용자는 명령어로 CLI를 실행하고, 접속할 서버 주소와 포트를 옵션으로 지정할 수 있어야 한다. | 예: `--host 127.0.0.1 --port 6380`. 지정하지 않으면 R-26과 같은 기본값 |
| R-34 | 사용자는 CLI에서 명령어와 인자를 공백으로 구분해 입력할 수 있어야 한다. | 예: `SET hello world` |
| R-35 | 사용자는 공백이 포함된 값을 따옴표로 감싸 입력할 수 있어야 한다. | 예: `SET msg "hello world"` |
| R-36 | CLI는 결과를 사람이 읽기 쉬운 형태로 출력해야 한다. | 없는 값은 `(nil)`, 오류는 `(error) 코드 메시지` |
| R-37 | CLI는 오류가 나도 종료되지 않고 다음 입력을 받아야 한다. | |
| R-38 | 사용자는 `exit` 입력이나 Ctrl+C로 CLI를 종료할 수 있어야 한다. | |
