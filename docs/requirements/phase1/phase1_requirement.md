# Mini Redis Phase 1 요구사항 명세서

Phase 1(해시 테이블 & 서버)에서 구현할 요구사항이에요.

## 1. 서버

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| R-01 | 사용자는 명령어로 서버를 켜고 끌 수 있어야 한다. | |
| R-02 | 사용자는 서버가 살아있는지 확인할 수 있어야 한다. | |
| R-03 | 서버는 모든 명령어 요청에 대해 동일한 구조의 응답을 반환해야 한다. | |
| R-04 | 사용자가 유효하지 않은 형태의 명령어를 입력하면, 서버는 오류를 반환해야 한다. | |

## 2. 해시테이블

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| R-05 | 레디스는 key-value 데이터를 저장하기 위한 해시테이블을 가지고 있어야 한다. | |
| R-06 | 레디스는 해시테이블의 초기 버킷 수를 8개로 생성해야 한다. | |
| R-07 | 레디스는 해시테이블이 가득 차기 전, 적재율이 0.75를 넘으면 해시테이블을 확장해야 한다. | 적재율은 (OCCUPIED + TOMBSTONE 버킷 수) / 전체 버킷 수예요 |
| R-08 | 레디스는 요청받은 key가 이미 값이 차 있는 index로 변환되면(collision), 비어 있는 가장 가까운 index를 찾아 저장해야 한다. | |
| R-20 | 해시테이블의 각 버킷은 state, key, key_len, value, value_len 필드를 저장해야 한다. | |
| R-21 | 버킷의 state는 EMPTY, OCCUPIED, TOMBSTONE 3가지 중 하나여야 한다. | |
| R-22 | 레디스는 해시테이블을 확장할 때 TOMBSTONE 상태의 버킷을 EMPTY로 변경해야 한다. | |

## 3. 해시 함수

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| R-09 | 레디스는 요청받은 key를 해시 함수를 사용해 해시테이블의 index로 변환해야 한다. | |
| R-10 | 해시 함수는 key 문자열을 입력받아 해시테이블 크기 내의 정수(0 ~ SIZE-1)를 반환해야 한다. | |

## 4. 데이터 규칙

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| R-11 | 사용자는 key에 해당하는 value값으로 NULL을 입력할 수 없다. | 조회 결과가 null(없음)인 경우는 해당 key가 저장된 적이 없거나 삭제된 경우 |
| R-12 | 레디스는 value에서 NULL과 빈 문자열("")을 구분해야 한다. | |
| R-23 | 레디스는 key의 길이(key_len)를 최대 99byte로 제한해야 한다. | |
| R-24 | 레디스는 요청 본문의 크기를 최대 1MB로 제한해야 한다. | value는 JSON 본문에 담기므로 1MB보다 조금 작아요 |
| R-25 | 사용자는 key와 value를 문자열로만 입력할 수 있다. 레디스는 문자열이 아닌 key나 value를 받으면 오류를 반환해야 한다. | 숫자나 객체를 저장하려면 클라이언트가 문자열로 바꿔서 보내요 (예: `json.dumps`) |

## 5. 명령어

### 5.1 SET

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| R-13 | 사용자는 SET key value를 입력해 저장소에 데이터를 저장할 수 있어야 한다. 레디스는 key가 변환된 index 위치에 value를 삽입해야 한다. | |
| R-14 | 사용자가 이미 존재하는 key에 대해 SET을 요청하면, 레디스는 기존 값을 덮어써야 한다. | |

### 5.2 GET

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| R-15 | 사용자는 GET key를 입력해 key에 해당하는 value를 조회할 수 있어야 한다. | |
| R-16 | 레디스는 key에 해당하는 value가 없으면 nil을 반환해야 한다. | |

### 5.3 DEL

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| R-17 | 사용자는 DEL key를 입력해 데이터를 삭제할 수 있어야 한다. 레디스는 key를 삭제하고, 삭제한 개수를 응답해야 한다. | |

### 5.4 EXISTS

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| R-18 | 사용자는 EXISTS key를 입력해 key 존재 여부를 확인할 수 있어야 한다. 레디스는 key가 저장소에 있으면 1을, 없으면 0을 응답해야 한다. | 예: `EXISTS user:1:name` |

### 5.5 DBSIZE

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| R-19 | 사용자는 저장소에 저장된 데이터 개수를 확인할 수 있어야 한다. | |
