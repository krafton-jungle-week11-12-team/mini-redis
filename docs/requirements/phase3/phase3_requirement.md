# Mini Redis Phase 3 요구사항 명세서

이 문서를 읽으면 Phase 3(동시성)에서 구현할 명령어와 각 명령어가 보장해야 하는 원자성 범위를 확인할 수 있어요. 요구사항 ID(R-39 ~ R-50)는 설계·테스트·구현에서 이 문서를 참조하는 기준이에요.

## 1. 값 교체

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| R-39 | 사용자는 GETSET key value로 값을 저장하면서 저장 전 값을 돌려받을 수 있어야 한다. 레디스는 이전 값이 없으면 nil을 응답해야 한다. | Redis 6.2부터 deprecated된 명령어지만, SET 옵션(`SET key value GET`)보다 구조 변경이 적어서 선택 |

## 2. 스크립트

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| R-40 | 사용자는 여러 명령어를 조합한 스크립트를 서버에서 원자적으로 실행할 수 있어야 한다. | optional, 후순위 |

## 3. 원자성

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| R-41 | 레디스는 명령어 하나가 실행되는 동안 다른 명령어가 끼어들지 않도록 원자성을 보장해야 한다. | 현재 구조에서 이미 만족. 서버(`http.server.HTTPServer`)가 단일 스레드라 요청을 하나씩 순서대로 처리해요 |

## 4. 일괄 처리

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| R-42 | 사용자는 MSET key1 val1 key2 val2 ...로 여러 key-value를 한 번에 원자적으로 저장할 수 있어야 한다. | |
| R-43 | 사용자는 MGET key1 key2 ...로 여러 key의 value를 한 번에 조회할 수 있어야 한다. | 팀 초안에는 없던 추가 제안 항목 |

## 5. 조건부 SET

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| R-44 | 사용자는 SETNX key value로 key가 없을 때만 값을 저장하는 것을 원자적으로 보장받아야 한다. 레디스는 저장하면 1을, 저장하지 않으면 0을 응답해야 한다. | SET 옵션(`SET key value NX`) 대신 사용 |
| R-45 | 사용자는 SETXX key value로 key가 있을 때만 값을 저장하는 것을 원자적으로 보장받아야 한다. 레디스는 저장하면 1을, 저장하지 않으면 0을 응답해야 한다. | 실제 Redis에는 없는 명령어. SET 옵션(`SET key value XX`) 대신 직접 정의 |

## 6. 카운터

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| R-46 | 레디스는 INCR·DECR 대상 value가 정수인지 확인하고, 정수가 아니면 오류를 반환해야 한다. | |
| R-47 | 사용자는 INCR key로 정수 value를 원자적으로 확인하고 1을 더할 수 있어야 한다. | |
| R-48 | 사용자는 DECR key로 정수 value를 원자적으로 확인하고 1을 뺄 수 있어야 한다. | |

## 7. 트랜잭션

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| R-49 | 사용자는 여러 명령어를 묶어 원자적으로 실행할 수 있어야 한다. | |
| R-50 | 사용자는 묶은 명령어를 실행하기 전에 지정한 key가 바뀌었으면 실행이 취소되도록 할 수 있어야 한다. | optional |
