# Mini Redis Phase 4 요구사항 명세서

이 문서를 읽으면 Phase 4(만료)에서 key에 만료 시간을 붙이고, 만료된 key를 지연 만료와 만료 청소기로 정리하는 규칙을 확인할 수 있어요. 요구사항 ID(R-51 ~ R-69)는 설계·테스트·구현에서 이 문서를 참조하는 기준이에요.

## 1. 만료

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| R-51 | 사용자는 key에 만료 시간(초)을 지정할 수 있어야 한다. 레디스는 초가 1 이상의 정수가 아니면 오류를 반환해야 한다. 레디스는 요청을 받은 시각에 지정한 초를 더해 만료 시각으로 저장해야 한다. | 예: `SET key1 val1 300`. 만료 시간의 최댓값은 설계에서 정해요 |
| R-52 | 레디스는 만료 시각을 YYYY-MM-DD HH:MM:SS 형식으로 저장해야 한다. | 지연 만료(R-53) 때 이 시각과 현재 시각을 비교해요. 시간대 기준(UTC / 로컬)은 설계에서 정해요 |
| R-65 | 사용자가 이미 만료 시간이 있는 key에 만료 시간을 다시 지정하면, 레디스는 새 시간으로 바꿔야 한다. | |
| R-69 | 레디스는 만료 시간이 있는 key 목록을 따로 관리해야 한다. | 2차. 만료 청소기(R-56)가 이 목록에서 key를 골라요 |

## 2. 버킷 필드

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| R-67 | 해시테이블의 각 버킷은 만료 시각을 저장하는 필드를 가져야 한다. | R-20의 버킷 필드에 추가해요 |
| R-68 | 레디스는 만료 시간이 없는 key의 만료 시각 필드를 '만료 없음' 값으로 저장해야 한다. | `None` 유력. `-1` 등 다른 값과 비교해 설계에서 확정해요 |

## 3. 지연 만료

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| R-53 | 레디스는 key를 조회하는 요청이 들어왔을 때만 그 key의 만료 여부를 확인하고, 만료됐으면 state를 TOMBSTONE으로 바꿔야 한다. | GET, EXISTS, TTL 등 key를 조회하는 모든 명령어에서 확인해요. EMPTY로 바꾸면 충돌로 밀려난 뒤쪽 key의 탐사가 끊겨서 TOMBSTONE으로 바꿔요 |

## 4. SET

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| R-66 | 사용자가 만료 시간 없이 SET으로 기존 key를 덮어쓰면, 레디스는 그 key의 만료 시간을 없애야 한다. | 예: `SET key1 val1 30` → `SET key1 val1`이면 만료 없음 |

## 5. TTL

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| R-64 | 사용자는 TTL key로 key의 남은 만료 시간(초)을 확인할 수 있어야 한다. | 예: `TTL key1`. 만료된 key의 응답(nil 등)은 설계에서 정해요 |

## 6. 리해싱

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| R-54 | 레디스는 적재율이 0.75를 넘으면 해시테이블을 확장하기 전에 만료 시각이 지난 key를 삭제해야 한다. | 만료 key를 찾으려면 전체 버킷을 순회해야 해서 비용이 커요. 삭제하지 않아도 될지 검토 중이에요 |
| R-55 | 레디스는 만료된 key를 삭제한 뒤에도 적재율이 0.75를 넘으면 해시테이블을 확장해야 한다. | |

## 7. 만료 청소기

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| R-56 | 레디스는 아무도 조회하지 않는 만료 key가 남지 않도록, 만료된 OCCUPIED key의 state를 주기적으로 바꾸는 만료 청소기를 가져야 한다. | 2차. 1차 확장 정책은 probe 때 만료 key를 확인해 TOMBSTONE으로 바꿔요 |
| R-57 | 만료 청소기는 1초에 최대 5번 실행되어야 한다. | |
| R-58 | 만료 청소기는 만료 시간이 있는 key 중 state가 OCCUPIED인 key만 골라 EMPTY나 TOMBSTONE으로 바꿔야 한다. | EMPTY로 바꾸면 탐사가 끊길 수 있어요(R-53). TOMBSTONE으로 통일할지 설계에서 정해요 |
| R-59 | 만료 청소기는 만료 시간이 있는 key의 1%(최대 200개)를 무작위로 골라야 한다. | |
| R-60 | 만료 청소기는 만료 시간이 있는 key가 20개 이하이면 전부 골라야 한다. | |
| R-61 | 만료 청소기는 실행 시간이 100ms를 넘으면 강제 종료해야 한다. | |
| R-62 | 만료 청소기는 고른 key 중 만료된 key가 25% 이상이면, 삭제한 뒤 다시 골라야 한다. | 재선택 반복은 100ms 제한(R-61) 안에서만 해요 |
| R-63 | 만료 청소기는 명령어를 처리하는 스레드와 같은 스레드에서 실행되어야 한다. | R-41의 단일 스레드 원자성 전제를 깨지 않게 해요 |
