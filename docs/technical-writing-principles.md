# 테크니컬 라이팅 원칙

문서를 리뷰할 때 아래 원칙을 기준으로 판단해요.
규칙을 기계적으로 적용하지 말고, 독자가 문서를 이해하고 행동하는 데 방해가 되는지 봐요.

## 한 페이지에서는 하나만 다루기

독자가 한 문서에서 하나의 목적을 달성할 수 있게 해요.
주제가 여러 개면 문서를 나누고 서로 링크해요.

**Incorrect:** [주제 A], [주제 B], [주제 C]를 한 문서에 함께 써요.

**Correct:** [주제 A] 문서와 [주제 B] 문서를 나누고, 필요한 곳에 링크를 걸어요.

## 가치를 먼저 제시하기

문서 앞부분에서 독자가 무엇을 알게 되거나 할 수 있는지 알려 줘요.
문서의 주제만 소개하면 독자가 계속 읽을지 판단하기 어려워요.

**Incorrect:** "이 문서는 [주제]를 설명해요."

**Correct:** "이 문서를 읽으면 [독자가 할 수 있게 되는 일]을 할 수 있어요."

## 속성 설명에 의미와 형식 함께 쓰기

파라미터, 속성, 용어를 설명할 때는 의미, 허용 형식, 사용 예시를 함께 써요.
이름만 있으면 독자가 직접 추측해야 해요.

**Incorrect:** `[이름]: [타입]`

**Correct:** `[이름]: [타입]` — [이 값의 의미]. [허용 형식]으로 입력해요. (예: [실제 값])
